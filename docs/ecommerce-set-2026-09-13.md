# 电商主图：商品套图

## 行为调整

编辑器默认生成 5 张，按购买决策分工：商品主图、使用场景、工艺特写、比例展示、结构细节。可选择 1–8 张；1 张仅生成主图，6–8 张依次增加搭配陈列、俯拍构图、氛围海报。每张都是独立图片，沿用整组 ZIP 下载。

过去的请求主要复用平台风格描述，并把首张生成图追加为后续图片的参考，容易重复布景、构图，或沿用生成图中已偏离原产品的细节。现在每张请求包含整套用途清单和当前图片的具体构图要求：主图完整展示商品，场景图保留环境，特写必须局部裁切，避免只换背景的一组完整商品照。

有产品原图时，每张都使用同一组原始参考，不追加生成结果。提示词要求保留外形、比例、部件、颜色、材质、印花和文字，未知背面或结构优先使用已知视角替代；参考照片的背景不作为产品身份。仍兼容纯文字生成：第一张建立干净主图，后续始终使用这一张作为固定产品参考。

平台选择影响拍摄要求，不替代套图分工。例如 Amazon 纯白底要求仅用于主图，后续仍按场景与细节用途生成。用户补充要求用于描述商品和场景偏好。

## 页面与接口

- 右侧增加两列套图内容清单，随张数更新，说明通过图标悬浮展示。
- 参考区提示上传同一商品的不同角度和细节，空态说明完整套图用途。
- 结果缩略图显示已保存的用途标签；历史结果没有标签时保留编号，不根据当前设置推断用途。
- `GET /api/v1/operations` 为 `ai.ecommerce` 返回 `ecommerce_plan`，前端与执行器共用 `backend/app/domain/ecommerce.py` 的分工定义。
- 新结果 metadata 保存 `shot_plan_version`、`shot_role`、`shot_label`；`identity_anchor` 区分 `original-references` 与 `first-output`。

## 启用与限制

无需新增数据库迁移。按正常发布流程更新前端、Web 和 Worker 后，尚未执行的电商任务使用新生成逻辑；已完成图片不会自动改变，需要重新提交任务。

同样张数仍为逐张调用，未增加额外图片生成步骤；默认张数从 4 调整为 5，报价仍按实际张数计算。沿用任务并发、排队、失败清理与退款机制。本次未部署线上环境。

产品一致性通过固定原始参考与构图约束改善，当前没有自动视觉一致性检测或像素级保真保证。尤其原有小字、复杂印花与未知视角仍受上游模型能力影响，正式验收需使用真实产品原图出一组套图并逐张对照。

- 前端全量：113 项通过；构建及类型检查通过。
- Ruff 检查、修改文件格式检查、Mypy 通过。
- 使用本地模拟接口和真实前端构建检查桌面与 390 像素手机宽度：5/8 张清单切换、结果标签、左右面板对齐、参数与提交区无横向溢出。模拟结果使用同一照片占位，仅用于布局验收，不代表真实生成效果。
- 未调用真实上游图片服务，尚未进行实际生成效果验收。
