# 基础编辑：图层与油漆桶

本次在已有基础编辑中增加真实像素图层，不调用 AI、不扣积分。右侧以「工具与颜色 / 图层」切换，同步显示当前图层。

## 操作

- 图层支持新建透明层、复制、删除、重命名、上下排序、显示/隐藏、锁定，以及 0–100% 不透明度。列表顶部图层覆盖下方图层，混合模式为正常（source-over）。至少保留一层。
- 画笔、橡皮擦、填充和清除只作用于当前层；隐藏、零不透明度或锁定图层不能绘制。选区与像素、图层属性和结构均接入撤销/重做。
- 矩形、椭圆、套索默认只选择当前图层中 alpha > 0 的内容，排除透明外部和内部镂空，不读取下方图层。空选区保持限制，不会意外填满全图。可关闭「只框选当前图层像素」框选空白区域；「选择内容」一次选中当前层全部非透明像素。
- 切换当前层清空选区，避免沿用其他图层的选区；Shift 加选、Alt 减选继续可用。
- 油漆桶快捷键 G。点击按 RGBA 容差（0–100）匹配，支持四向连通或全图同色。填充与遍历均受现有选区限制，点击选区外无效果。
- 油漆桶默认参考所有可见图层，在当前层写入颜色，可在新透明层沿原产品区域填色；也可只参考当前层。透明像素匹配忽略隐藏 RGB。

## 保存与兼容

- `POST /api/v1/assets/{id}/edit` 接受原有 `image` 和可选 `project` 文件；旧版仅传 PNG 的调用继续有效。
- 保存为新的 `image.edit` 素材，PNG 为合成结果，独立图层另存为同目录 `raster-project-v1.bin`。服务端验证图层并重新合成 PNG，确保保存结果与图层一致。
- 素材 metadata 的 `raster_project_ready` 标识版本是否可继续分层编辑。前端加载当前 PNG，并通过同源、鉴权、禁缓存的 `GET /assets/{id}/edit/project` 同时读取图层文档；读取失败明确报错，不悄悄丢弃图层。
- 新版本重新打开保留图层像素、名称、顺序、不透明度、可见性、锁定和当前层。选区与撤销历史仅保留在本次编辑中。「还原原图」恢复打开时的文档。
- 下载 PNG 是合成图，不是 PSD。经裁切、AI 等其他工具生成的版本使用其自身图片作为一层，不继承尺寸或像素已失配的旧图层。
- 图层对象纳入素材保存失败清理、删除队列和孤儿对象扫描；软删除宽限期内可恢复，管理员清理也会移除附属对象。没有数据库迁移。

## 文档格式与资源限制

4 字节小端 manifest 长度 + UTF-8 JSON + 从底到顶的 PNG 字节串；manifest 包括 version=1、width、height、activeId 与每层 id/name/visible/locked/opacity/byteLength。PNG 全部为同尺寸 RGBA。头部最高 16 KiB，文件最高 128 MiB，另遵守账号和站点的图片+图层合计上传限制。

源图最高 1600 万像素，图层数量上限 `min(12, floor(192000000 / (width * height * 4)))`，例如 2000×2000 最多 12 层、4000×4000 最多 3 层。该限制控制当前层像素预算，不代表编辑器进程的总内存上限。历史最多 30 步、约 96 MB 额外共享缓冲，至少保留一步。像素编辑与 PNG 编解码都在 Worker 内执行，预览最长边 1400，保存保持原始尺寸。

## 验证

- 像素测试覆盖分层编辑、叠放与不透明度、隐藏/锁定、复制后独立修改、结构撤销、笔画取消、内容框选与内部透明孔、油漆桶容差/连通/全图/选区边界。
- 前端交互测试覆盖油漆桶设置、图层操作、默认内容框选、图层载入和随 PNG 保存；文档编解码覆盖精确字节与畸形输入。
- 后端测试覆盖原有绘制/擦除恢复、图层规范化与合成、无积分扣费、跨用户访问拒绝、损坏输入、软删除恢复及最终清理。
- 本轮前端全量 135 项通过；后端素材、选区、裁切及基础编辑累计 39 项通过。前端构建、Ruff 和配置内 Mypy 检查通过，新图层文档模块额外通过 Mypy。
- 本地浏览器运行真实 Worker 及服务端图层规范化：新增透明图层填色、仅选当前层 17,871 个内容像素、修改可见性与不透明度、保存并重开两层文档均通过。实际导出图中填色为 RGBA(255,102,0,130)，其余区域透明；图层不透明度为 51%，原图层保持隐藏。1280×720 与 390×844 布局已检查。
