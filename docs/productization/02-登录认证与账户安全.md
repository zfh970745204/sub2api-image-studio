# 02 登录认证与账户安全

## 1. 功能范围

- 邮箱或用户名 + 密码登录。
- 安全退出、全部设备退出、修改密码。
- 管理员创建/邀请用户、禁用与解禁用户。
- 可选邮箱验证和忘记密码；邮件服务未配置时隐藏入口。
- 登录设备列表、最近登录时间和异常登录记录。
- 首个超级管理员通过服务器交互式 CLI 创建，不在代码或 `.env` 中写默认密码。

首发采用服务端会话，不把长期 JWT 放在浏览器 `localStorage`。Cookie 使用 `HttpOnly + Secure + SameSite=Lax`。

## 2. 权限与规则

| 行为 | 游客 | 用户 | `users.manage` |
|---|---:|---:|---:|
| 登录/申请重置 | 是 | 是 | 是 |
| 查看和修改本人资料 | 否 | 是 | 是 |
| 查看本人会话/踢出本人设备 | 否 | 是 | 是 |
| 创建、禁用、解锁用户 | 否 | 否 | 是 |
| 强制退出其他用户 | 否 | 否 | 是 |

规则：

- 密码使用 Argon2id，禁止可逆加密和明文日志。
- 连续失败按 IP + 账号双维度限流；达到阈值短时锁定，但不得泄露账号是否存在。
- 用户被禁用或密码修改后，`session_version` 增加，使旧会话立即失效。
- 管理员不能查看用户密码，也不能设置一个用户未知的永久密码；采用临时链接或强制首次修改。

## 3. 数据库结构

```text
users
- id uuid PK
- email citext UNIQUE
- username citext UNIQUE NULL
- password_hash varchar
- display_name varchar
- avatar_asset_id uuid NULL
- status varchar                  # pending/active/disabled/locked
- locked_until timestamptz NULL   # 临时锁定截止时间
- email_verified_at timestamptz NULL
- session_version int DEFAULT 1
- permission_version int DEFAULT 1
- last_login_at timestamptz NULL
- created_at timestamptz
- updated_at timestamptz
- deleted_at timestamptz NULL

auth_sessions
- id uuid PK
- user_id uuid FK users
- token_hash char(64) UNIQUE      # Cookie 随机值只保存哈希
- session_version int
- ip_hash char(64)
- user_agent varchar
- expires_at timestamptz
- last_seen_at timestamptz
- revoked_at timestamptz NULL
- revoke_reason varchar NULL
- created_at timestamptz

password_reset_tokens
- id uuid PK
- user_id uuid FK users
- token_hash char(64) UNIQUE
- expires_at timestamptz
- consumed_at timestamptz NULL
- created_at timestamptz

login_attempts
- id uuid PK
- account_fingerprint char(64)
- ip_hash char(64)
- success boolean
- failure_code varchar NULL
- created_at timestamptz
```

数据库对 `users.email`、`auth_sessions.token_hash`、`password_reset_tokens.token_hash` 建唯一索引，对会话过期时间和登录尝试时间建清理索引。

## 4. 接口设计

```text
POST /api/v1/auth/login
POST /api/v1/auth/logout
POST /api/v1/auth/logout-all
GET  /api/v1/auth/me
POST /api/v1/auth/password/change
POST /api/v1/auth/password/forgot
POST /api/v1/auth/password/reset
GET  /api/v1/auth/sessions
DELETE /api/v1/auth/sessions/{session_id}

GET  /api/v1/admin/users
POST /api/v1/admin/users
GET  /api/v1/admin/users/{user_id}
PATCH /api/v1/admin/users/{user_id}
POST /api/v1/admin/users/{user_id}/disable
POST /api/v1/admin/users/{user_id}/enable
POST /api/v1/admin/users/{user_id}/revoke-sessions
```

登录成功只设置会话 Cookie并返回脱敏用户信息。所有改变身份状态的接口记录审计日志。

## 5. 首个管理员

服务器执行：

```bash
docker compose exec web python -m app.cli create-admin
```

CLI 交互输入邮箱和密码，创建后立即失效，不保存默认凭据。后续管理员全部在后台通过角色分配完成。

## 6. 验收标准

- Cookie 无法被前端 JavaScript 读取，HTTPS 下不会明文发送。
- 密码修改、用户禁用、全部退出后旧会话立即失效。
- 登录错误信息不区分“账号不存在”和“密码错误”。
- 登录、退出、重置、禁用和会话吊销均有测试与审计记录。

## 7. 实施结果

- [x] 支持邮箱或用户名登录、当前设备退出、全部设备退出、本人资料修改和密码修改。
- [x] 密码采用 Argon2id；会话值与一次性设置/重置值均使用随机令牌，数据库只保存 HMAC-SHA256 哈希。
- [x] 会话 Cookie 固定为 `HttpOnly + SameSite=Lax`，生产配置强制 `Secure`、HTTPS 公网地址和两项独立强认证密钥。
- [x] 登录失败按账号指纹与 IP 指纹分别统计连续失败，达到阈值后进入有明确截止时间的短时锁定；所有失败响应不区分账号是否存在。
- [x] `auth_sessions` 每次鉴权同时校验账号状态、过期时间和 `session_version`；改密、禁用、全部退出及管理员强退会立即使旧会话失效。
- [x] 支持查看本人设备、近期异常登录及逐个吊销；用户不可读取原始会话值或 IP，仅返回设备 User-Agent、活动时间与失败类型/时间。
- [x] 管理员创建用户时只生成一次性设置链接，不接受永久密码；支持列表、详情、资料修改、禁用、解锁/启用和强制退出。
- [x] `python -m app.cli create-admin` 交互读取邮箱与两次密码，不接收命令行密码；已有 `super_admin` 后拒绝再次引导创建。
- [x] 身份变更与登录失败均在同一数据库事务写入 `outbox_events`，载荷不含密码、Cookie 或原始设置/重置令牌，供文档 11 转为正式审计日志。
- [x] 已建立 `users`、`auth_sessions`、`password_reset_tokens`、`login_attempts` 及所需唯一/清理索引；同时提前建立与文档 03 兼容的最小 `roles/user_roles` 骨架。
- [x] 忘记密码接口保持账号枚举安全；在文档 08 接入邮件发送器前公开能力标志为关闭，前端不得显示入口。管理员设置链接和令牌重置流程已可用。
