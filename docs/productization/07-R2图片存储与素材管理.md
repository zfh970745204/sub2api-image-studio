# 07 R2 图片存储与素材管理

## 1. 功能范围

- 上传原图、结果图、遮罩、SVG 和缩略图存储到 Cloudflare R2。
- R2 桶保持私有，通过后端授权生成短时下载地址。
- 每个资产记录所有者、对象键、哈希、尺寸、类型、来源任务和版本链。
- 用户管理自己的素材、版本和下载；管理员按权限排查违规或孤儿对象。
- 支持软删除、延迟物理删除、套餐保留期和数据迁移。
- 抠图页面中的本地预览背景仍仅存在浏览器，不上传 R2。

## 2. 权限与安全规则

| 行为 | 用户 | `assets.read` | `assets.manage` |
|---|---:|---:|---:|
| 上传/查看/下载本人资产 | 是 | 是 | 是 |
| 删除本人资产 | `assets.delete_own` | 否 | 是 |
| 查看任意用户资产 | 否 | 是 | 是 |
| 恢复/强制删除资产 | 否 | 否 | 是 |

规则：

- 对象键由服务端生成，不能使用用户文件名拼接路径。
- 数据库不保存永久签名 URL，只保存 `bucket + object_key`。
- 下载接口先验证资产归属/权限，再返回 5-15 分钟签名 URL或代理流。
- 上传文件必须校验真实格式、大小、像素、解码能力并移除 EXIF。
- R2 凭据只允许最小桶权限，不能使用 Cloudflare 全局 API Key。

## 3. 对象键规范

```text
users/{user_id}/{yyyy}/{mm}/{asset_id}/original.png
users/{user_id}/{yyyy}/{mm}/{asset_id}/result.png
users/{user_id}/{yyyy}/{mm}/{asset_id}/thumb.webp
users/{user_id}/{yyyy}/{mm}/{asset_id}/mask.png
users/{user_id}/{yyyy}/{mm}/{asset_id}/vector.svg
```

对象元数据不保存邮箱、用户名、提示词等隐私信息。文件名仅作为数据库展示字段。

## 5. 接口设计

首发优先走 API 接收、校验、规范化后上传 R2，避免未验证文件直接进入桶。流量增大后再增加预签名直传。

```text
POST /api/v1/assets/upload
GET  /api/v1/assets?cursor=&kind=&root_id=
GET  /api/v1/assets/{asset_id}
GET  /api/v1/assets/{asset_id}/lineage
POST /api/v1/assets/{asset_id}/download-url
DELETE /api/v1/assets/{asset_id}
POST /api/v1/assets/{asset_id}/restore

GET  /api/v1/admin/assets
GET  /api/v1/admin/assets/{asset_id}
POST /api/v1/admin/assets/{asset_id}/quarantine
POST /api/v1/admin/storage/orphans/scan
POST /api/v1/admin/storage/orphans/reconcile
```

`download-url` 返回短时地址和过期时间；对于高敏资产可由后端代理下载，不向前端暴露 R2 域名。

## 6. 生命周期与一致性

- 数据库先创建 `uploading` 记录，再上传 R2，成功后标记 `ready`。
- R2 成功但数据库失败时，由孤儿扫描任务按对象标签回收。
- 用户删除先软删除，延迟 7 天进入物理删除队列；积分/审计引用只保留资产 ID 和摘要。
- 保留期限按任务创建时会员快照或当前产品政策执行，并提前通知用户。
- R2 生命周期规则只做兜底，业务删除由数据库队列驱动。

## 7. 验收标准

- 未登录、越权和过期签名地址均无法访问对象。
- 数据库和对象键可按资产 ID 双向追踪。
- 上传中断、重复上传和删除重试不会产生永久孤儿对象。
- 当前本地 `backend/data/results` 能通过迁移工具上传并校验 SHA-256。

- [x] 上传先按当前会员快照限制字节数和像素数，再识别真实 PNG/JPEG/WebP/SVG 格式；栅格图统一解码、旋转转正并移除 EXIF，SVG 拒绝脚本、事件处理器、DTD、实体和外部资源。

- [x] 用户素材列表、详情、版本链、下载、软删除和恢复接口均执行所有者隔离；管理员只读预览写入 `admin_preview` 访问日志，隔离、恢复、强制删除和孤儿回收要求 `assets.manage`。

- [x] 报价和建单都会重新验证 `source_asset_id` 所有权与 `ready` 状态。Worker 启动时安装真实执行器，从 R2 读取并校验输入哈希，执行 Sub2API/本地操作，再将输出作为新版本写回 R2 和 `output_asset_id`。
- [x] 管理接口可扫描数据库缺失对象与 R2 孤儿对象；对账会隔离对象缺失的资产，并仅回收超过安全宽限期的无记录对象。
