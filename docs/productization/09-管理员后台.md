# 09 管理员后台

## 1. 功能范围

管理员后台使用独立 `/admin` 路由与后台布局，服务于日常运营，不与用户图片编辑器混在同一页面。

### 页面模块

| 页面 | 核心能力 |
|---|---|
| 总览 | 今日用户、任务成功率、积分收支、队列、Sub2API/R2 状态 |
| 用户 | 搜索、状态、角色、会员、余额、任务和资产摘要 |
| 会员 | 套餐定义、权益、用户开通/续期/变更 |
| 积分 | 全站流水、人工调整、审批、冲正和对账异常 |
| 价格 | 操作启停、基础积分、参数加价、版本和生效时间 |
| 任务 | 队列、状态、耗时、错误、重试和退款状态 |
| 资产 | 所有者、存储状态、大小、保留期、隔离和删除队列 |
| 系统配置 | Sub2API、R2、邮件、业务开关、连接测试和发布历史 |
| 角色权限 | 角色、权限点和用户授权 |
| 审计日志 | 操作者、动作、对象、时间、结果和请求 ID |

## 2. 权限设计

后台路由和按钮按权限点展示，API 再次强制校验。建议菜单规则：

```text
/admin                         admin.dashboard.read
/admin/users                   users.read
/admin/memberships             memberships.read
/admin/points                  points.read
/admin/pricing                 pricing.read
/admin/jobs                    tasks.read
/admin/assets                  assets.read
/admin/settings                config.read
/admin/roles                   roles.read
/admin/audit                   audit.read
```

高风险操作需输入原因并打开确认对话框：禁用用户、积分调整、会员立即降级、任务强制退款、资产隔离、配置发布和角色变更。

## 3. 数据库结构

后台主要读取各领域表，额外维护运营操作记录：

```text
admin_action_requests
- id uuid PK
- action_type varchar
- target_type varchar
- target_id uuid
- payload jsonb                    # 不含密钥明文
- reason varchar
- risk_level varchar               # normal/high/critical
- status varchar                   # pending/approved/rejected/executed/failed
- requested_by uuid FK users
- approved_by uuid FK users NULL
- executed_at timestamptz NULL
- created_at timestamptz

admin_saved_views
- id uuid PK
- owner_id uuid FK users
- module varchar
- name varchar
- filters jsonb
- columns jsonb
- created_at timestamptz
- updated_at timestamptz
```

所有领域写入仍由对应领域服务执行，后台页面不能绕过积分、会员、任务或配置状态机直接改表。

## 4. 接口设计

各领域接口见对应文档，后台聚合接口补充如下：

```text
GET  /api/v1/admin/dashboard/summary?range=7d
GET  /api/v1/admin/dashboard/timeseries?metric=jobs&range=30d
GET  /api/v1/admin/search?q=
GET  /api/v1/admin/action-requests
POST /api/v1/admin/action-requests
POST /api/v1/admin/action-requests/{id}/approve
POST /api/v1/admin/action-requests/{id}/reject
GET  /api/v1/admin/export/{module}              # 异步生成脱敏 CSV
```

列表统一游标分页、服务端筛选和排序。导出属于高风险数据访问，必须限制权限、记录审计并设置短时下载链接。

## 5. 交互要求

- 后台为安静、紧凑的工作界面：左侧固定导航、顶部全局搜索、主区表格/详情抽屉。
- 状态使用文字 + 图标，不能只依赖颜色。
- 列表支持搜索、筛选、排序、分页、空状态、加载失败和重试。
- 详情页显示完整时间线，将用户、任务、积分流水和资产关联起来。
- 危险按钮使用明确动作名称，例如“禁用账号”，不用模糊的“确定”。
- 密钥输入框永不展示旧值；已配置状态显示掩码、更新时间和最近测试结果。

## 6. 总览指标

- 活跃用户、注册数、会员分布。
- 任务数、成功率、P50/P95 耗时、排队长度、失败原因 Top N。
- 积分发放、消费、退款、人工调整、异常差额。
- R2 存储量、当日新增、孤儿对象和删除失败。
- Sub2API 请求量、成功率、429/5xx 和估算成本。

所有指标从业务事实表或聚合表计算，不能仅依赖易丢失的 Redis 计数。

## 7. 验收标准

- 不同后台角色只看到和调用被授权模块。
- 任一高风险写操作都能从页面追踪到领域记录和审计日志。
- 管理员页面不能显示密码、会话令牌、完整 API Key 或 R2 Secret。
- 10 万级用户/任务列表仍采用服务端分页，不一次性加载全表。
