# 05 积分账户与计费

## 1. 功能范围

- 每个用户拥有一个积分账户和可查询余额。
- 支持管理员赠送、扣减、活动赠送、任务消费和失败退款；账本预留会员周期发放类型。
- 用户查看积分流水、关联任务、变化值和余额快照。
- 管理员查询全站流水并人工调整，必须填写原因。
- 余额变化通过不可变流水记录，禁止直接在数据库手工改余额。

积分是站内使用额度，不等同现金。首发不支持提现、转账和用户间赠送。

## 2. 权限与规则

| 行为 | 用户 | `points.read` | `points.adjust` |
|---|---:|---:|---:|
| 查看本人余额与流水 | 是 | 是 | 是 |
| 查看任意用户流水 | 否 | 是 | 是 |
| 调整积分 | 否 | 否 | 是 |
| 修改/删除已有流水 | 否 | 否 | 否 |

关键规则：

- 所有积分均使用整数，不允许小数。
- 首发积分不自动过期；未来需要过期时新增积分批次，不修改旧流水语义。
- 普通消费后余额不得小于零。
- 人工负向调整不得把余额扣成负数，除非由受控债务功能另行设计。
- 流水一旦写入不可更新和删除；错误调整通过一条反向流水冲正。
- 每个业务动作使用唯一 `reference_type + reference_id + entry_type` 防止重复。

## 3. 数据库结构

```text
point_accounts
- id uuid PK
- user_id uuid FK users UNIQUE
- balance bigint CHECK(balance >= 0)
- lifetime_earned bigint
- lifetime_spent bigint
- version int
- status varchar                    # active/frozen
- created_at timestamptz
- updated_at timestamptz

point_transactions
- id uuid PK
- account_id uuid FK point_accounts
- user_id uuid FK users
- entry_type varchar                # grant/consume/refund/adjust/renewal/promotion/reversal
- delta bigint                     # 正数增加，负数消费
- balance_before bigint
- balance_after bigint
- reference_type varchar            # job/membership/admin/promotion
- reference_id uuid
- idempotency_key varchar
- request_fingerprint varchar NULL
- description varchar
- metadata jsonb
- actor_user_id uuid NULL
- created_at timestamptz
- UNIQUE(user_id, idempotency_key)
- UNIQUE(reference_type, reference_id, entry_type)

point_adjustment_requests
- id uuid PK
- user_id uuid FK users
- amount bigint
- reason varchar
- status varchar                    # pending/approved/rejected/applied
- requested_by uuid FK users
- approved_by uuid FK users NULL
- transaction_id uuid NULL
- idempotency_key varchar
- request_fingerprint varchar
- review_idempotency_key varchar NULL
- review_fingerprint varchar NULL
- created_at timestamptz
- reviewed_at timestamptz NULL
```

首发可让 `super_admin` 或 `points.adjust` 直接应用小额调整；大额调整阈值以上采用双人复核，阈值由管理员安全配置。

## 4. 原子扣费算法

任务创建与扣费在同一个 PostgreSQL 事务中完成：

```sql
UPDATE point_accounts
SET balance = balance - :cost,
    lifetime_spent = lifetime_spent + :cost,
    version = version + 1
WHERE user_id = :user_id AND balance >= :cost
RETURNING balance;
```

更新成功后写入消费流水和任务；更新不到行则返回积分不足。任务失败时使用任务 ID 创建唯一退款流水并原子增加余额。重试退款因唯一约束只能成功一次。

## 5. 接口设计

```text
GET  /api/v1/points/balance
GET  /api/v1/points/transactions?cursor=&limit=

GET  /api/v1/admin/points/accounts
GET  /api/v1/admin/points/transactions?user_id=&entry_type=&reference_type=&cursor=&limit=
GET  /api/v1/admin/users/{user_id}/points
POST /api/v1/admin/users/{user_id}/points/adjustments
GET  /api/v1/admin/point-adjustments?status=&cursor=&limit=
POST /api/v1/admin/point-adjustments/{id}/approve
POST /api/v1/admin/point-adjustments/{id}/reject
POST /api/v1/admin/point-transactions/{id}/reverse
```

积分不足统一返回：

```json
{
  "code": "INSUFFICIENT_POINTS",
  "message": "积分不足",
  "details": {"balance": 8, "required": 20}
}
```

## 6. 对账与补偿

- 每日对账任务校验账户余额等于所有流水 `delta` 汇总。
- 账户级差异会记录审计事件并把账户冻结为 `frozen`。
- 成功任务消费、最终失败任务退款等任务级对账在文档 06 引入任务表和状态机后一并接入。
- 发现差异只报警和冻结相关账户，不自动篡改账本。

## 7. 验收标准

- 100 个并发扣费请求不会产生负余额。
- 相同幂等键重复提交只产生一条流水。
- Worker 多次报告失败只退款一次。
- 管理员调整、审批、冲正均记录操作者、原因和审计日志。

## 8. 实施结果

- [x] 新增 `point_accounts`、`point_transactions` 和 `point_adjustment_requests`，由 `20260908_0005` 迁移为存量用户创建账户，并按首次激活策略补齐 20 分赠送流水。
- [x] 首次激活、管理员邀请激活和 CLI 创建首个管理员均接入幂等赠送；即使赠送配置为 0，也保留零值流水作为永久发放标记。
- [x] 余额通过带状态及余额条件的 `UPDATE ... RETURNING` 原子修改，负向操作不能形成负余额；100 个并发消费请求仅允许余额覆盖范围内的请求成功。
- [x] 流水同时使用 `(user_id, idempotency_key)` 和 `(reference_type, reference_id, entry_type)` 去重，请求指纹会拒绝同一幂等键承载不同操作。
- [x] PostgreSQL 使用触发器禁止更新或删除积分流水；错误操作通过反向流水冲正，原流水及冲正流水均保留完整审计信息。
- [x] 实现本人余额与流水查询，以及全站账户、全站流水、用户积分详情和调整申请列表等管理接口。
- [x] 小于配置阈值的人工调整立即应用；达到阈值的调整必须由另一名具备 `points.adjust` 权限的管理员审批，申请、审核和冲正均要求原因与 `Idempotency-Key`。
- [x] 提供任务消费和失败退款服务，退款必须匹配原任务消费金额，重复失败回报只生成一条退款流水；与任务创建事务及状态机的最终接线由文档 06 完成。
- [x] Scheduler 每日执行账户级对账，发现余额与流水汇总不一致时只记录审计并冻结账户，不自动修改账本。
- [x] P0 继续保持会员 `periodic_points=0`，不运行自动周期积分发放；会员周期积分属于后续 P1 能力。
- [x] 自动化测试覆盖首次赠送、查询权限、人工调整、双人审批、冲正、幂等冲突、并发消费、单次退款和差异冻结。
