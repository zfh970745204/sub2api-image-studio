# 08 系统配置与密钥管理

## 1. 功能范围

管理员在后台配置并测试：

- Sub2API：接口地址、API Key、图片模型、超时和启用状态。
- Cloudflare R2：Endpoint、Account ID、Bucket、Access Key ID、Secret Access Key、区域。
- 邮件：SMTP/API 服务、发件人、凭据和启用状态。
- 业务参数：注册开关、默认会员、默认积分、上传限制、签名 URL 时长、任务并发等。
- 配置草稿、连接测试、发布、回滚和变更历史。

普通工作台不再允许修改 Sub2API 配置；顶部仅显示“服务可用/维护中”。现有 `/api/settings` 必须迁移为管理员接口并删除匿名写能力。

## 2. 必须保留的启动根配置

以下三项不能存进同一个业务数据库，否则应用在连接数据库或解密配置前无法读取它们，并形成循环依赖：

```text
DATABASE_URL
REDIS_URL
APP_CONFIG_MASTER_KEY
```

它们应由 Docker Secret、宝塔受限配置文件或云密钥服务提供。除此之外，Sub2API、R2、邮件等业务密钥全部在管理员后台配置。`APP_CONFIG_MASTER_KEY` 使用 256 位随机值，不能进入 Git、数据库、日志或前端。

## 3. 权限与审批

| 行为 | `config.read` | `config.test` | `config.manage` |
|---|---:|---:|---:|
| 查看脱敏状态 | 是 | 是 | 是 |
| 测试连接 | 否 | 是 | 是 |
| 保存草稿/发布/回滚 | 否 | 否 | 是 |
| 查看密钥明文 | 否 | 否 | 否 |

- GET 接口只返回非敏感值、`has_value`、末四位和更新时间。
- 保存时空密钥表示保留原值；清除密钥使用独立高风险接口。
- 修改 R2、Sub2API 和邮件密钥必须二次确认、填写原因并写审计。
- 生产环境可要求 `config.manage` 双人审批后发布。

## 4. 数据库结构

```text
config_groups
- id uuid PK
- code varchar UNIQUE                # sub2api/r2/email/general
- name varchar
- active_version int
- updated_at timestamptz

config_versions
- id uuid PK
- group_id uuid FK config_groups
- version int
- status varchar                     # draft/active/superseded/failed
- values jsonb                       # 仅非敏感字段
- created_by uuid FK users
- published_by uuid FK users NULL
- change_reason varchar
- created_at timestamptz
- published_at timestamptz NULL
- UNIQUE(group_id, version)

encrypted_secrets
- id uuid PK
- config_version_id uuid FK config_versions
- key_name varchar
- ciphertext bytea
- nonce bytea
- key_version int
- value_fingerprint char(64)
- last_four varchar NULL
- created_at timestamptz
- UNIQUE(config_version_id, key_name)

config_test_runs
- id uuid PK
- group_id uuid FK config_groups
- config_version_id uuid FK config_versions NULL
- requested_by uuid FK users
- status varchar                     # running/succeeded/failed
- result_code varchar
- result_message_redacted varchar
- latency_ms int NULL
- created_at timestamptz
- completed_at timestamptz NULL
```

密钥采用 AES-256-GCM 加密，每条记录使用独立 nonce，并把配置组和键名作为附加认证数据。解密仅发生在后端服务内存，异常日志必须过滤请求头、表单和密钥字段。

## 5. 接口设计

```text
GET  /api/v1/admin/config
GET  /api/v1/admin/config/{group}
POST /api/v1/admin/config/{group}/drafts
PATCH /api/v1/admin/config/{group}/drafts/{version}
POST /api/v1/admin/config/{group}/drafts/{version}/test
POST /api/v1/admin/config/{group}/drafts/{version}/publish
POST /api/v1/admin/config/{group}/versions/{version}/rollback
POST /api/v1/admin/config/{group}/secrets/{key}/clear
GET  /api/v1/admin/config/{group}/history
```

连接测试由后台任务执行：

- Sub2API：调用模型列表或低成本鉴权接口，不执行付费图片生成。
- R2：在专用 `_health/` 前缀写入、读取并删除随机小对象。
- 邮件：验证连接；发送测试邮件必须由管理员再次确认目标地址。

## 6. 运行时加载

- Web/Worker 从配置服务读取当前激活版本，缓存 30-60 秒。
- 发布后发送 Redis 失效事件；各实例拉取新版本并报告加载结果。
- 新版本加载失败时继续使用上一有效版本并告警。
- 任务创建时记录 Sub2API 配置版本，但绝不复制密钥到任务参数或日志。

## 7. 管理页面

每个配置组包含：当前状态、脱敏字段、草稿编辑、连接测试、发布按钮、历史版本和回滚。密钥输入框永不回显旧值，保存成功后立即清空浏览器状态。

## 8. 验收标准

- 普通用户与运营管理员无法访问配置接口。
- 数据库快照、API 响应、日志和审计中都没有密钥明文。
- 配置发布不要求重启服务，失败会自动保留上一有效版本。
- 轮换 Sub2API/R2 密钥后，新任务使用新版本，运行中任务行为可追踪。

## 9. 实施结果

- [x] `20260908_0008` 新增 `config_groups`、`config_versions`、`encrypted_secrets` 和 `config_test_runs`，并初始化 `sub2api`、`r2`、`email`、`general` 四个配置组。
