# 12 测试验收与质量门禁

## 1. 测试范围

- 单元测试：权限计算、会员权益、积分公式、价格规则、任务状态机、对象键生成。
- 集成测试：PostgreSQL 事务、Redis 队列、R2 兼容存储、Sub2API 模拟服务。
- 契约测试：API 请求/响应、错误码、分页、幂等键。
- E2E：登录、上传、报价、扣费、任务、结果、下载、后台调整与配置发布。
- 并发与故障测试：重复提交、Worker 崩溃、上游超时、R2 失败、退款重试。
- 视觉与无障碍测试：桌面/移动布局、键盘、对比度和状态页。

## 2. 权限测试矩阵

每个受保护接口至少覆盖：

```text
未登录 -> 401
已登录但无权限 -> 403
有权限且访问本人资源 -> 200/业务结果
普通用户访问他人资源 -> 404（避免枚举）
后台角色访问授权资源 -> 200 + audit_log
后台角色缺少具体权限 -> 403
```

测试用户固定包含 `user/operator/finance/auditor/super_admin` 和至少两个不同所有者。

## 3. 测试数据库结构

生产表结构不增加“测试字段”。测试运行使用独立临时数据库和命名空间，辅助表仅存在测试环境：

```text
test_runs
- id uuid PK
- git_sha varchar
- suite varchar
- environment varchar
- status varchar
- started_at timestamptz
- completed_at timestamptz NULL
- summary jsonb
```

CI 的 PostgreSQL、Redis、S3 兼容服务每次运行后整体销毁，禁止连接生产数据库或生产 R2 桶。

## 4. 测试辅助接口

生产环境不暴露测试注入接口。测试环境可以启用受构建标志保护的内部接口：

```text
POST /internal/test/reset
POST /internal/test/fake-sub2api/scenario
POST /internal/test/worker/run-next
GET  /internal/test/outbox
```

应用在 `APP_ENV=production` 时必须拒绝启动任何 `/internal/test/**` 路由。更优先直接通过测试夹具控制依赖，不依赖 HTTP 测试后门。

## 5. 必测场景

### 积分与任务

- 并发 100 次相同幂等请求只扣一次。
- 余额刚好足够时成功，少 1 分时不创建任务。
- 上游 400、401、429、500、超时分别进入正确重试/退款路径。
- Worker 在上传 R2 前后崩溃都不产生重复结果或重复退款。
- 管理员改价后，旧报价和旧任务价格保持不变。

### R2 与资产

- 越权下载返回 404，签名过期失效。
- 上传伪装扩展名、超大像素、损坏文件和恶意 SVG 被拒绝。
- 数据库/R2 单边成功时补偿任务可恢复一致性。

### 配置与密钥

- 配置发布、失败回退、版本回滚和缓存失效。
- GET 永不返回旧密钥，空值保留，清除走独立接口。
- 测试日志和错误堆栈不包含密钥样本。

### UI

- 360/390/768/1280/1440 宽度截图差异审核。
- 页面无水平溢出、按钮文字截断和模态框遮挡。
- 键盘焦点顺序、ARIA 名称和 reduced motion 生效。

## 6. 质量门禁

合并到主分支必须满足：

- Python：Ruff、类型检查、单元/集成测试通过。
- TypeScript：类型检查、生产构建、组件测试通过。
- 核心领域覆盖率不低于 90%，整体覆盖率不低于 80%。
- 数据库迁移具备 upgrade/downgrade 或明确不可逆说明。
- 依赖漏洞扫描无未接受的高危/严重问题。
- 权限、积分、密钥和 R2 改动必须由第二位开发者评审。

## 7. 上线验收

- 在类生产环境完成一次全链路任务和失败退款。
- 用备份恢复 PostgreSQL，并抽样验证 R2 对象哈希。
- 完成旧资产迁移演练和回滚演练。
- 监控、告警、值班联系人和运行手册已配置。
