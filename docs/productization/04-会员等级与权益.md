# 04 会员等级与权益

## 1. 功能范围

- 管理员创建、启用、停用和排序会员等级。
- 设置会员名称、标识、周期赠送积分、操作折扣、并发任务数、文件限制和保存天数。
- 管理员为用户开通、续期、升级、降级或取消会员。
- 用户查看当前等级、权益、生效时间和到期时间。
- 到期由调度任务处理，变更过程保留事件历史。

首发不包含在线支付。会员由管理员人工分配，后续接支付时复用相同会员订单与权益模型。

## 2. 权限与业务规则

| 行为 | 用户 | `memberships.read` | `memberships.manage` |
|---|---:|---:|---:|
| 查看本人会员 | 是 | 是 | 是 |
| 查看所有会员记录 | 否 | 是 | 是 |
| 管理套餐定义 | 否 | 否 | 是 |
| 调整用户会员 | 否 | 否 | 是 |

规则：

- 同一用户同一时刻只能有一个 `active` 会员。
- 角色与会员完全分离，开通最高会员也不会获得后台权限。
- 套餐修改只影响后续权益周期；用户已获得积分不回收。
- 降级默认在当前周期结束后生效，管理员强制立即变更必须填写原因。
- 周期积分发放使用唯一周期键，重复调度不得重复赠送。

## 3. 数据库结构

```text
membership_plans
- id uuid PK
- code varchar UNIQUE
- name varchar
- description text
- level int UNIQUE
- status varchar                    # draft/active/inactive
- billing_period varchar            # none/month/year，首发仅作权益周期
- periodic_points int
- operation_discount_bps int        # 10000=原价，8000=八折
- max_concurrent_jobs int
- max_upload_mb int
- max_image_megapixels int
- asset_retention_days int
- display_order int
- created_by uuid FK users
- created_at timestamptz
- updated_at timestamptz

plan_entitlements
- id uuid PK
- plan_id uuid FK membership_plans
- entitlement_code varchar
- value jsonb
- UNIQUE(plan_id, entitlement_code)

user_memberships
- id uuid PK
- user_id uuid FK users
- plan_id uuid FK membership_plans
- status varchar                    # scheduled/active/expired/cancelled
- starts_at timestamptz
- ends_at timestamptz NULL
- auto_renew boolean DEFAULT false
- source varchar                    # admin/payment/promotion/migration
- assigned_by uuid FK users NULL
- reason varchar NULL
- entitlement_snapshot jsonb         # 当前周期不可变权益快照
- created_at timestamptz
- updated_at timestamptz

membership_events
- id uuid PK
- membership_id uuid FK user_memberships
- event_type varchar                # created/activated/renewed/upgraded/downgraded/expired/cancelled
- old_plan_id uuid NULL
- new_plan_id uuid NULL
- effective_at timestamptz
- actor_user_id uuid NULL
- reason varchar NULL
- idempotency_key varchar NULL
- request_fingerprint varchar NULL
- created_at timestamptz
```

对 `user_memberships(user_id, status)` 建部分唯一索引，保证一个有效会员。套餐删除采用停用，不能物理删除已被引用的套餐。

## 4. 接口设计

```text
GET  /api/v1/membership/me
GET  /api/v1/membership/plans             # 仅返回启用且可展示的套餐

GET  /api/v1/admin/membership-plans
POST /api/v1/admin/membership-plans
GET  /api/v1/admin/membership-plans/{id}
PATCH /api/v1/admin/membership-plans/{id}
POST /api/v1/admin/membership-plans/{id}/activate
POST /api/v1/admin/membership-plans/{id}/deactivate

GET  /api/v1/admin/users/{user_id}/memberships
POST /api/v1/admin/users/{user_id}/memberships
POST /api/v1/admin/memberships/{id}/renew
POST /api/v1/admin/memberships/{id}/change-plan
POST /api/v1/admin/memberships/{id}/cancel
```

会员变更接口请求包含 `effective_mode=now|period_end`、目标套餐、结束时间和必填原因，并要求 `Idempotency-Key`。

## 5. 权益计算

后端提供统一 `EntitlementService`，返回当前用户的生效快照：

```json
{
  "plan_code": "pro",
  "discount_bps": 8500,
  "max_concurrent_jobs": 3,
  "max_upload_mb": 40,
  "retention_days": 90
}
```

任务创建时把会员与折扣快照写入任务计价记录，任务执行期间会员到期不改变已确认价格。

## 6. 验收标准

- 同一用户不能出现两个同时生效的会员。
- 套餐调整、续期和到期均有事件记录与审计记录。
- 重复执行周期发放任务不会重复赠送积分。
- 会员等级不会影响后台菜单或管理员权限。

## 7. 实施结果

- [x] 新增 `membership_plans`、`plan_entitlements`、`user_memberships` 和 `membership_events`，并由 `20260908_0004` 迁移种子化 Free / Basic / Pro 及补齐存量有效用户的 Free 会员。
- [x] 使用 PostgreSQL 部分唯一索引保证每个用户最多一个 `active` 会员；服务层同时限制每个用户最多一个待生效变更。
- [x] 用户通过设置链接首次激活及 CLI 创建首个管理员时自动获得长期 Free；读取权益时若发现到期或历史缺失，会在同一事务修复为应生效套餐或 Free。
- [x] 实现统一 `EntitlementService`，返回折扣、并发、上传、像素和保留期；会员周期写入不可变 `entitlement_snapshot`，套餐修改不追溯改变已有周期。
- [x] 实现用户本人套餐/权益查询，以及套餐创建、读取、修改、启停、用户历史、人工分配、续期、立即或周期末变更、取消等管理接口。
- [x] 分配、续期、变更和取消强制要求 `Idempotency-Key`，事件记录保存请求指纹；相同请求返回原记录，同一键用于不同请求时返回冲突。
- [x] 所有套餐和会员管理动作写入 `membership.audit` outbox，会员生命周期同时写入事件历史；角色授权仍完全由 RBAC 决定。
- [x] Scheduler 每分钟处理到期和待生效会员；到期无后续套餐时自动回落 Free，不启用自动续期。
- [x] P0 按冻结结论保持 `periodic_points=0`，不运行周期积分发放；周期赠送与唯一周期账务键随文档 05 的账本在 P1 实现。
- [x] 自动化测试覆盖套餐种子、默认会员、单 active 约束、权限隔离、套餐管理、权益快照、续期、立即/周期末变更、取消、到期、事件审计和幂等重放。
