# 11 审计安全与风控

## 1. 功能范围

- 记录登录、权限、会员、积分、任务处置、资产访问和配置变更。
- 对登录、上传、任务创建、报价和下载进行分层限流。
- 防止越权访问、重复扣费、恶意大图、提示词滥用和成本失控。
- 管理员查看安全事件、封禁账号/IP 指纹并导出脱敏审计材料。
- 建立依赖扫描、密钥扫描、备份加密和事件响应流程。

## 2. 权限设计

| 行为 | 权限点 |
|---|---|
| 查看审计日志 | `audit.read` |
| 查看安全事件 | `security.events.read` |
| 管理封禁和限流策略 | `security.policies.manage` |
| 导出审计数据 | `audit.export` |

管理员查看其他用户原图属于高敏行为，要求 `assets.read`，并记录 `admin_preview` 审计。密钥明文不对任何角色开放。

## 3. 数据库结构

```text
audit_logs
- id uuid PK
- occurred_at timestamptz
- actor_user_id uuid NULL
- actor_role_snapshot jsonb
- action varchar
- target_type varchar
- target_id uuid NULL
- result varchar                     # success/denied/failed
- request_id varchar
- ip_hash char(64)
- user_agent varchar NULL
- reason varchar NULL
- changes_redacted jsonb
- metadata jsonb

security_events
- id uuid PK
- event_type varchar
- severity varchar                   # low/medium/high/critical
- user_id uuid NULL
- ip_hash char(64) NULL
- request_id varchar NULL
- status varchar                     # open/investigating/resolved/ignored
- details_redacted jsonb
- resolved_by uuid NULL
- resolved_at timestamptz NULL
- created_at timestamptz

access_blocks
- id uuid PK
- subject_type varchar                # user/ip_fingerprint
- subject_hash varchar
- reason varchar
- starts_at timestamptz
- ends_at timestamptz NULL
- created_by uuid FK users
- created_at timestamptz
```

审计日志采用追加写。生产数据库角色禁止应用执行 `UPDATE/DELETE audit_logs`。

## 4. 接口设计

```text
GET  /api/v1/admin/audit-logs
GET  /api/v1/admin/audit-logs/{id}
POST /api/v1/admin/audit-logs/export
GET  /api/v1/admin/security/events
POST /api/v1/admin/security/events/{id}/resolve
GET  /api/v1/admin/security/blocks
POST /api/v1/admin/security/blocks
POST /api/v1/admin/security/blocks/{id}/revoke
GET  /api/v1/admin/security/rate-limits
PATCH /api/v1/admin/security/rate-limits/{policy}
```

审计接口默认隐藏 IP 原值、密钥、提示词全文和图片内容；确有业务需求时采用专项权限和受控查看流程。

## 5. 安全控制

### Web

- HTTPS、HSTS、CSP、`X-Content-Type-Options`、合理的 `Referrer-Policy`。
- 会话 Cookie 安全属性、Origin/Referer 校验、CSRF 防护。
- 所有 SQL 参数化，SVG 下载使用安全响应头，不内联执行用户 SVG。
- 上传内容按实际解码识别，不信任扩展名和 Content-Type。

### 成本与滥用

- 登录、报价、创建任务分别按 IP、用户和会员并发限制。
- 单用户同时运行任务数由会员权益决定，全站有熔断阈值。
- Sub2API 429 或连续 5xx 触发退避和熔断，防止重试扩大成本。
- 单日积分消费异常、短时间大量失败、重复上传哈希触发安全事件。

### 数据

- R2 私有桶、最小权限凭据、短时签名地址。
- 数据库和备份加密，备份文件不与生产主机只保留同一份。
- 日志字段白名单，异常对象先清洗再写日志。
- 依赖锁定版本并定期执行漏洞与许可证扫描。

## 6. 保留策略

- 审计日志在线保存至少 180 天，之后归档到受控存储。
- 登录尝试和限流明细保存 30-90 天。
- IP 使用带服务端 salt 的哈希，不长期存原始 IP，除非当地合规要求明确允许。
- 用户删除账号后按政策匿名化业务记录，但保留法律与账务所需的最小审计信息。

## 7. 验收标准

- OWASP Top 10 基础检查无高危问题。
- 跨用户 ID、签名 URL、管理员接口均有越权测试。
- 日志、错误响应、前端状态、数据库非密文字段中搜索不到测试密钥。
- 限流、熔断和全站任务并发阈值可被监控并安全恢复。
