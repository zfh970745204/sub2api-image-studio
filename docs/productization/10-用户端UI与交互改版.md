# 10 用户端 UI 与交互改版

## 1. 设计目标

把现有单页工具升级为适合重复工作的图片生产台。视觉应专业、清晰、克制，以内容和操作效率为主，不采用营销页式大卡片、装饰渐变或过度动画。

## 2. 信息架构

```text
/login                         登录
/forgot-password               找回密码
/app                           工作台概览
/app/studio                    图片编辑器
/app/assets                    素材库与版本
/app/jobs                      任务中心
/app/points                    积分余额与流水
/app/membership                会员与权益
/app/profile                   个人资料、安全与设备
/admin/*                       管理后台
```

### 工作台布局

- 桌面端：左侧主导航、中间图片画布、右侧参数/结果面板。
- 平板：工具栏横向化，参数区移到画布下方。
- 手机：顶部紧凑导航、稳定比例画布、底部操作区，任何控件不得造成页面横向溢出。
- 图片生成、抠图、放大、修复等保留独立工具视图和版本链。

## 3. 功能需求

### 全局导航

- 展示积分余额、会员标识、任务通知和账号菜单。
- 积分不足时在提交前展示所需积分和当前余额。
- 后台入口只对拥有任一后台权限的账号展示。

### 图片编辑器

- 操作按钮同时显示预计积分，点击后先弹出简洁报价确认。
- 任务提交后显示排队/进度，不用全屏遮罩长期锁住页面。
- 支持离开页面后在任务中心继续跟踪。
- 结果成功后自动加入版本链和 R2 素材库。
- 智能抠图背景色/本地背景图仍只用于预览，不创建资产、不扣积分。
- 下载前检查资产权限并获取短时下载地址。

### 素材与任务

- 素材库支持网格/列表、类型、日期、任务和版本筛选。
- 任务中心区分排队、运行、成功、失败、已退款。
- 失败任务展示用户可理解的原因、退款状态和可否重试。

### 积分与会员

- 顶部余额点击进入流水页。
- 流水明确显示“消费/退款/赠送/调整”、关联操作和余额。
- 会员页显示当前权益和有效期；首发不展示未接入的在线购买按钮。

## 4. 权限与页面守卫

| 页面/动作 | 权限或条件 |
|---|---|
| `/app/**` | 已登录且账号为 active |
| 创建图片任务 | `studio.use + tasks.create`，且会员权益和积分满足 |
| 查看素材/任务 | 本人所有权或对应后台权限 |
| 删除素材 | `assets.delete_own` 且无运行任务依赖 |
| `/admin/**` | 至少一个 `admin.*` 权限点 |

前端守卫只改善体验，后端必须重复校验。收到 `401` 跳登录，`403` 显示无权限页，积分不足显示余额入口而不是无权限页。

## 5. 数据库结构

UI 不单独复制业务数据，用户偏好可保存：

```text
user_preferences
- user_id uuid PK FK users
- theme varchar DEFAULT 'light'
- locale varchar DEFAULT 'zh-CN'
- studio_layout jsonb
- notification_preferences jsonb
- updated_at timestamptz

user_notifications
- id uuid PK
- user_id uuid FK users
- type varchar
- title varchar
- body varchar
- target_url varchar NULL
- read_at timestamptz NULL
- created_at timestamptz
```

布局偏好必须经过服务端白名单校验，不能存任意 HTML/CSS。

## 6. 接口设计

前端复用各领域接口，增加：

```text
GET   /api/v1/app/bootstrap             # 当前用户、权限、会员、余额、服务状态
GET   /api/v1/me/preferences
PATCH /api/v1/me/preferences
GET   /api/v1/me/notifications
POST  /api/v1/me/notifications/{id}/read
POST  /api/v1/me/notifications/read-all
```

`bootstrap` 只聚合首屏必要数据，不返回密钥和庞大历史列表。

## 7. 视觉规范

- 8px 基础间距系统；卡片圆角不超过 8px。
- 正文至少 14px，紧凑元数据至少 12px；不使用随视口缩放字体。
- 主色、强调色、成功、警告、危险和中性色分工明确，避免单一色系统治页面。
- 按钮使用 Lucide 图标；工具类命令优先图标并提供 tooltip/aria-label。
- 画布、工具栏、缩略图和积分数字使用稳定尺寸，加载和状态变化不能推动布局跳动。
- 所有颜色满足 WCAG AA；键盘焦点清晰；状态不能只靠颜色表达。
- 动画仅用于状态过渡，尊重 `prefers-reduced-motion`。

## 8. 页面状态清单

每个页面必须覆盖：加载、空数据、成功、校验错误、网络错误、401、403、服务维护、积分不足、任务排队和移动端。禁止用空白页或浏览器原生错误代替产品状态。

## 9. 验收标准

- 360、390、768、1280、1440 宽度无横向溢出和文字重叠。
- 键盘可完成登录、导航、上传、报价确认和后台常用操作。
- 用户提交任务后可离开编辑器并从任务中心继续跟踪。
- 预览背景不上传、不扣积分，透明下载文件保持透明通道。
